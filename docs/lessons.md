# Lessons from building ztorrent

Rules extracted from the history of one cross-platform Electron app (46 commits,
0.1.0 → 0.3.1). Each rule is followed by the incident that produced it, because the
incident is what makes the rule stick.

---

## 1. Distribution: the install is part of the product

**Ship a one-line installer, and treat it as real software.**
Most people meet the app on a release page reached from a link, not from the README.
The shortest path from that page to a running app is a `curl … | sh`, so it goes at the
top of every release's notes — generated by CI, and re-applied to releases that were
made by hand or by an earlier attempt at the same tag.

**Anchor asset matching to the end of the filename.**
Matching `-mac-x64.dmg` loosely also matched the `.dmg.blockmap` electron-builder
publishes beside it: a 200kB download that will not mount.

**Match architecture against every spelling, not one.**
The same build is `x64` in the dmg, `x86_64` in the AppImage and `amd64` in the deb —
each packager names artifacts by its own convention.

**Version download links by tag, not by `/releases/latest/`.**
When artifact names carry the version, a `latest/` link with `0.1.0` in the filename
404s the day the next release lands. A tag link only goes stale.

**Never require sudo.** `/Applications` when writable, `~/Applications` otherwise;
`~/.local/bin` plus a desktop entry on Linux. Nothing outside `$HOME` unless the
system already allows it.

**Set `artifactName` explicitly.** NSIS otherwise emits `ztorrent Setup 1.0.0.exe`,
and spaces in a filename are awkward in a release URL.

**The `.deb` packager needs `author.email`.** It is the mandatory maintainer field, and
its absence only surfaces on a full Linux build — an unpacked `--dir` pack skips deb
and passes.

### Shell-script hazards worth knowing before you write the installer

- **Keep the script pure ASCII.** bash 3.2 (`/bin/sh` on macOS) scans identifiers by
  the locale's character rules, so a multi-byte character touching `$VAR` is read as
  part of its name. `$ARCH…` expanded as one unset name and `set -u` aborted the
  install. Bracing the variable fixes one line; going pure ASCII — assembling every
  glyph from `printf` octal escapes — removes the whole class in every locale, and
  still puts UTF-8 on the wire.
- **Call system binaries by full path.** `/usr/bin/xattr`, not `xattr`. The PyPI
  package of that name installs an executable taking different arguments; anyone who
  has it got a usage error instead of a de-quarantined app, and on an unsigned build
  macOS then refuses to open what was just installed, with nothing in the output to
  explain why.
- **Subshells inherit `errexit`.** A backgrounded download whose `curl` exited non-zero
  died before writing its status file, and the poll waiting on that file spun until
  killed. Every 404 hung the installer.
- **Reaping a killed child returns 128+SIGTERM**, which `errexit` turns into an exit —
  from inside the `EXIT` trap, so cleanup stopped before removing the temp directory.
- **Degrade in steps, not all at once.** Non-UTF-8 locale → ASCII bar; `NO_COLOR` or a
  dumb terminal → no colour; a pipe → plain lines with no redraw.
- **Draw your own progress bar** if you care what it looks like: `curl --progress-bar`
  cannot be styled. Run the transfer quietly in the background and render from the
  size of the file as it lands.

**Test matrix that actually caught things:** `en_US.UTF-8`, `tr_TR.UTF-8`, `C`, unset
locale; piped and on a tty; `NO_COLOR` with `LC_ALL=C`; bash 3.2.

## 2. Auto-update without a signing certificate

**Unsigned builds rule out Squirrel and the platform update services** — both want a
signature before they will replace an application. What is left is doing by hand what
the installer already does: read the latest release off the API, pick the artifact
matching this platform and arch, put it where the running copy lives.

**The installer and the updater must agree on artifact naming.** A change to one is a
change to both. Say so in the docs next to both.

**The swap cannot run while the app holds its own files open.** Write a small detached
`/bin/sh` script that waits for your pid to exit, then swaps.

**Move the old copy aside; do not delete it.** A failed copy is put back, so the worst
case is the version you already had starting up again.

**Do the fallible part while the UI can still report it.** The `.app` is lifted out of
the `.dmg` while the app is still running — a failure there reaches the user; one after
quitting does not.

**Nothing downloads before a check finds something genuinely newer; nothing swaps until
the user asks.** A staged build survives a normal quit, and a check that finds the same
version — or cannot reach the network — keeps the staged copy rather than asking for
the same 100MB twice.

**Refuse to run unpackaged.** In a dev run `app.getPath('exe')` points at
`Electron.app`, and the swap would happily replace it.

**Per-platform reality:** macOS swaps the `.app`; Linux swaps the AppImage *and only
when running from one* (a `.deb` install belongs to the package manager); Windows hands
the NSIS installer the job, since it already knows how to stop, replace and restart.

**Make it testable without publishing.** Two env vars did it:
`ZTORRENT_UPDATE_FEED` (a local release JSON) and `ZTORRENT_UPDATE_PRETEND_VERSION`.

**Carry the whole flow in one control.** A single status-bar pill moves through
available → downloading → preparing → "Restart to update", and clicking it does the
next thing. No modal, no separate progress window.

**Check the About box.** It claimed `1.0.0` whatever the build was.

## 3. CI and releases

- **`fail-fast: false` on the platform matrix.** One platform failing should not hide
  the other two's artifacts.
- **Set `CSC_IDENTITY_AUTO_DISCOVERY: false`** when there is no Developer ID, or
  electron-builder hunts for a signing identity and logs a failure instead of building
  unsigned.
- **`npmRebuild: false`** when every native dep ships N-API prebuilds. N-API is
  ABI-stable across Node and Electron, so `@electron/rebuild` has nothing to do —
  leaving it on just makes node-gyp download Electron headers, which is the one step
  that needs the network and the one step that fails behind a filtered connection.
- **Cut releases with the `gh` CLI already on the runner** rather than a third-party
  action.
- **`gh release create` refuses a tag that already has a release.** Check first and
  upload into it; otherwise the installers strand as run artifacts that expire.
- **`if-no-files-found: error`** on artifact upload, and a `test -n "$(ls -A release)"`
  before publishing. A silent empty release is worse than a failed job.
- **Watch action runtime deprecations** — the v4 line targeted Node 20 and every job
  grew an annotation.

## 4. UI decisions

**Colour is a budget. Spend it on state, not on chrome.**
Sidebar icons were all ink-dim, so the one thing the list is sorted by — what state a
torrent is in — was the one thing the eye had to read word by word. Colouring them was
free because the colours already existed: downloading takes its progress bar's blue,
seeding the same green, completed the violet of a finished bar. *Aliases of semantic
tokens, never fresh hex*, so the mapping lives in one place and follows both themes.

**Things that are structure, not state, stay neutral.** "Torrents", the label tags, "New
Label" hold every state at once, so no single colour is theirs. Leaving them alone is
what keeps five accents from becoming eleven.

**One meaning per accent.** Selection in the main list means "these are what the toolbar
will act on" — so it keeps the blue. Choosing a category or a detail-table row only
changes what you are looking at, so those take a chromaless tint.

**Selection should tint, not repaint.** A solid accent row with white text overrode
every colour inside it — a seeding torrent's green bar turned white the moment you
clicked it — and required a whole family of `.selected` overrides that existed only to
undo the repaint. Tinting deleted all of them.

**Verify contrast numerically before arguing about typography.** Four commits fought
over the progress-bar label's weight and smoothing; the actual problem was white at
1.5:1 on a light fill. Once the fills were deepened to ~3.5:1 the label went back to
regular weight at 13px and the font-smoothing override disappeared. *Also:* antialiased
font smoothing thins strokes, which is invisible for dark-on-light and guts white text
on a light fill.

**Take fills from a real colour system.** Hand-mixed and luminance-matched is even but
arbitrary; Radix step 9 is the step specified for solid backgrounds carrying white text.
And check hue distance, not just name — green 9 sits 55° from the blue and reads as a
cooler blue beside it in a list; grass is 75° away and reads as its own colour.

**States that look alike must not be alike.** "Finished" shared seeding's green, so a
torrent that had stopped giving back looked identical to one still doing it.

**A mode the user cannot see is a support ticket.** Alternate speed limits showed only
as a toggle in the same soft blue every other toggle wears — speeds dropped and the
swarm got the blame. The fix: amber in the toolbar *and* the status bar at once, plus a
faint red wash and a 1px ring around the whole window. The wash sits **above** the
modals (the throttle does not lift while a dialog is open) and is **pointer-events:
none**, so every click still lands. Both controls also name the state in their tooltip,
for anyone who cannot use the colour.

**If it looks clickable, bind it.** The status-bar speed pill had a `clickable` class, a
hover state and a tooltip saying what it toggled — and nothing bound to it for two
releases. *The readout you are looking at should also be the switch.*

**Every path that changes state must refresh every view of it.** Recurring bug, three
times: the Options checkbox went stale when the toolbar flipped the switch; the toolbar
button went stale when Options did, because `settings-changed` redrew only the status
bar; the Light/Dark radios were ticked once when the menu was built and never again.
Route all of them through one function.

**Shortcuts for things people do when the room changes.** Light/dark was three levels of
menu deep. `Cmd/Ctrl+L` was free, and it goes through the same `setTheme` as the radios
so it persists and moves the native chrome too.

**Do not let the user reach a state that is easy to enter and awkward to leave.** The
View menu could hide the sidebar, detail pane and status bar. Dropping the items — and
the state, styles and guards behind them — was a net deletion. Splitters still resize.

**Follow the platform's input conventions exactly.** `mousedown` selected the row under
the pointer unconditionally, so pressing on one of several selected rows to start a drag
collapsed the selection to that row. Finder and Explorer hold that collapse until
`mouseup`: drag and the selection goes with it, release without dragging and it
collapses. `dragstart`/`dragend` cancel the pending collapse so a drop does not undo its
own selection.

**Offer what the user last did, not a fixed default.** The Add sheet filled Save In from
`downloadPath` every time, so adding a season an episode at a time meant picking the same
folder over and over. `lastSavePath` is offered instead, with the preference as fallback
— and changing the preference clears it, so that stays the deliberate override.

**A dropdown of what exists beats a free-text box.** The label field was a `datalist`
that never had anything to suggest, because a typed label was written onto the torrent
but never registered — so it reached neither the sidebar nor the next sheet.

**Constrain the customisation set on purpose.** Sixteen symbols and eight colours for
labels, drawn to the same 24-grid and stroke weight as the rest of the set. A hundred
glyphs would make labels harder to tell apart, not easier. Colours are CSS tokens, not
hex, so a label keeps its *identity* across themes rather than its *value*; the default
leads the list because it is the absence of a choice.

**Derive a logo from constants, and emit every copy from them.** The mark's steps shift
by the same amount because the geometry is computed, not hand-placed; the same script
emits the icon, the SVG and the renderer glyph, so dock, About box and empty state
cannot drift.

**One source of wording, one source of numbers.** `statusText()` baked the percentage
into the "checking" case while the cell appended it to every incomplete state, giving
"Checking 42.0 % 42.0 %". It only showed up sometimes, because a recheck of a complete
torrent takes the other branch. Deleting the special case was the whole fix.

## 5. State, persistence and async

**Snapshot what the UI needs onto your own record; do not read it off a live object.**
The piece map, file list, tracker URLs and metadata were read off the live WebTorrent
object, so stopping a torrent — or just reopening the app — emptied those tabs for a
torrent whose data was sitting on disk. The same root cause made selected-size wrong: with
no live file list it fell back to the full size, so a stopped torrent reported files it
had been told not to download.

**Every async pane must check the answer still belongs to the current selection.** Tables
repainted a beat later and got away with it; a canvas is drawn once and kept, so a
torrent with nothing to draw left the *previous* torrent's pieces on screen. Drop ticks
and replies that arrive after the selection moved on, and blank the canvas when there is
nothing to draw. A static dialog is worse — the mismatch cannot correct itself.

**Decide, per setting, whether it is a preference or a decision about this afternoon.**
Alternate speed limits persisted across restarts, so the app came up claiming a throttle
it was not applying. They are now session-only — reset on read, left out of what is
written — while the two *rates* still persist.

**One helper reads the effective value.** Both throttles now consult the flag; saving
preferences used to go through an `applySettings` that knew only about the normal pair
and quietly restored full speed.

**Be consistent about sentinel values.** A zero alternate rate stalled the swarm instead
of removing the cap, unlike every other rate field in the app.

**Atomic writes: temp file + rename.** A crash mid-save must not leave a truncated
settings file.

**Every stored value needs a fallback path out of the file.** A symbol name that goes
stale renders a grey tag rather than a row with no icon; a pre-feature state file and a
corrupt one both load as empty rather than throwing. And delete rather than store when a
value returns to default, so the file does not collect entries for things only looked at.

**Migrate saved layouts conditionally and idempotently.** Reordering columns is useless
to existing users, whose saved order wins. The migration runs only when the two columns
are still exactly where the older build left them — adjacent and immediately ahead of
Down Speed — so a hand-arranged layout is left alone and running it twice changes
nothing.

**Escape user strings in generated markup.** A label containing a double quote broke the
sidebar's HTML through a `data-` attribute.

**Know what the library's API actually does.** `torrent.pause()` only refuses *new*
peers; wires already connected keep sending at full speed. Pausing for real means
clearing piece selections and recomputing interest.

## 6. Security and privacy: fail closed

**A partial guarantee is worse than none.** A proxy that covers announces but leaks peer
connections costs speed and hides nothing — the address the swarm records is the one the
peers see. So whatever cannot be routed under a policy is *switched off*, not sent
around: LSD, uTP, UPnP and `udp://` trackers under either policy; DHT and the inbound
listeners under a proxy too.

**Enumerate every channel that carries your address outward** and route each explicitly:
peer dials, tracker announces, web-seed fetches. Resolve names at the proxy so nothing
leaks to the local resolver.

**Patch narrowly.** `net.connect` is swapped only for the synchronous window in which the
library drains its queue, so nothing else in the app sees a patched `net` module.

**Re-read the interface address per connection.** A VPN reconnecting on a new address is
picked up without a restart, and one that vanishes stops everything rather than falling
back to the physical NIC — that is the kill switch.

**Secrets go to the OS keychain, and a denied keychain must not destroy them.** A refused
read returns empty while preserving the sealed value.

**Renderer sandbox is a real boundary.** Context isolation, no Node, and one explicit
allow-list of named channels in the preload — including for *events*, not just invokes.

**Tests for this category earn their keep.** The egress suite caught two things review
did not: `dial()` calling the `net.connect` it had itself patched, and closing the
inbound listeners before the client reached `listening` — which is what releases every
torrent into discovery, so it would have stalled all of them.

## 7. Platform grit

- **macOS document icons:** declaring the document type twice — once by hand for the UTI
  and `LSHandlerRank: Owner`, once generated from `fileAssociations` — meant only the
  generated entry named an icon while the hand-written one outranked it, so every
  `.torrent` file wore the generic page. The entry Launch Services binds must be the one
  that names an icon.
- **Unsigned means quarantine.** Document the right-click ▸ Open path and the
  `/usr/bin/xattr -dr com.apple.quarantine` line, and say plainly in the README that the
  warning is expected.
- **AppImage needs `libfuse2`** on Debian/Ubuntu. Put it in the troubleshooting section;
  it is the single most common "won't start".
- **Some targets cannot be built from your machine.** Windows was covered by CI only.

## 8. Working practice

**Write the README for whoever wants to open a torrent.** The first version was 272 lines
opening with an ASCII diagram of the window, reaching npm scripts, CI and proxy semantics
before saying how to install anything. What survived: install, first launch, how to add a
torrent, what to do when it will not open. Everything else moved to `docs/development.md`
unchanged — not deleted, relocated.

**Make the app scriptable for your own tests.** `--add=`, `--shot=`, `--shot-tabs`,
`--shot-quit`, and a `window.ztorrentUI` exposing the same actions the toolbar triggers.
Screenshots and UI assertions stop being manual.

**Test the failing paths, not the happy one.** Both installer bugs — the errexit
subshell and the trap that exited from inside itself — were found by testing a 404 and a
dropped connection, never by a successful install.

**State how a change was verified, in the commit.** "Verified against a local release: the
pill through every state, the restart sheet in both themes, staging across a restart, and
the swap script's three outcomes." That sentence is what makes the commit trustworthy a
month later.

**Write commit bodies that explain the mechanism.** Nearly every rule above was
recoverable only because the commit said *why the bug existed*, not what the diff did.

**Deletion counts as a feature.** Hidden panes, the `.selected` override family, the
`statusText` special case, the font-smoothing hack — four changes that shipped as net
removals.
